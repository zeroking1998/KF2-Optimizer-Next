## Evidence-gated laboratory scope

| ID | Decision and concrete reason |
|---|---|
| L01 Gameplay telemetry | KF2's own `Launch.log` provides bounded process-bound session context and AI/wave snapshots. A pinned official-SDK-compiled schema-6 viewport bridge preserves KF2's viewport behavior and creates a separate probe only in a standalone gameplay world. The probe adds read-only freshness-limited enemy class/boss/visibility/LOD/animation/injury and exact special-move buckets; corpse physics/visibility/age/runtime-budget, exact detached-limb/ragdoll-warning and four runtime-collision decisions; five decal managers; official smoke/fire/toxic/puke-mine/explosion categories; gore/world/ground-fire/impact particle; and FleX-surrogate aggregates. Its separately policy-gated corpse actuator is not a telemetry source. The probe destroys itself outside `NM_Standalone`; general per-actor snapshots and exact creation events remain unavailable, while each confirmed Optimizer distance-sleep, proximity-wake and visible-ragdoll-sleep receipt carries a session-local `corpse_id`, distance and effective-awake readback. The optional per-action corpse-ID marker reuses that exact ID for ten seconds, draws only recently rendered line-of-sight corpses, and is bounded to 24 standalone-session entries. |
| L02 Enemy rendering | KF2/UE3 native view-frustum and occlusion culling already prevents drawing living-enemy primitives outside the camera or behind occluders. Shipped global graphics/decal/shadow/material/detail controls and read-only actual LOD/render/material/attachment observations are implemented. The optimizer deliberately adds no `bHidden` or per-enemy hide/show mutation, preventing invisible-enemy pop and gameplay errors. |
| L03 Enemy animation | Actual animation LOD, required-bone, native skip/interpolation, offscreen tick and kinematic-distance states are read-only diagnostics. Changing them can affect hit readability and remains excluded without a verified neutral contract. |
| L04 Corpses/ragdolls | `MaxDeadBodies`, lifetimes and shipped collision switches are reversible. Protected telemetry observes active/sleep/final-pose, visibility, LOD, injury, age, capacity and official offscreen rules. Its independently reported corpse capability treats the selected 4-2000 value as the stable user ceiling. Reaching it alone performs no cleanup: a fresh current sample and sustained pressure against the exact target-relative 60/59, 60/58 and 60/57 bands must both be present before a separate runtime threshold drops in bounded steps and KF2 drains excess corpses one at a time. Current recovery stops removal immediately and restores capacity gradually toward the selected ceiling. Distant physics is separate and distance-first: an old slow offscreen corpse beyond 3,500 units may sleep every 1,000 ms without FPS pressure; visible living/corpse density or confirmed frame pressure moves entry to 2,500/1,800 units and 500/250 ms. Tracked bodies wake inside 1,500 units. Reversible `MinLodModel` and the later visible-ragdoll stage remain frame-pressure-only. Living enemies/collision remain unchanged and every actuator pauses during Zed Time. |
| L05 Gore/decals/particles | Verified limits/lifetimes/distance policy plus actual wound/splatter/pool/impact/explosion decal counts, gore/world/ground-fire/impact particle counts, visibility, LOD and bounds are implemented. Spray/explosion actors expose official gameplay-capable semantics; exact creation events and per-effect simulation cost remain gated. |
| L06 Advanced FleX | The legacy crashing proxy remains discarded. Its independently rebuilt minimal replacement has 37 exact PE forwarders plus fifteen local ABI relays, including exact set/wait fence, solver bounds, parameter-call and six particle/phase/velocity bulk-transfer observations, offline-only gating, identity-bound observations and control, transactional install/restore and automated loader soak. Transfer and parameter payloads are never read or changed. Hysteresis-stabilized Adaptive substep control covers 1-5 with warmup and stale-control fallback. Historical gameplay observations belong to an older candidate and are not treated as proof for the current uncommitted build. The low-level API still does not identify living enemies, active corpses or inactive corpses, so the program never guesses semantic solver groups. |
| L07 Adaptive performance | The complete V2 target registry and deterministic governor exist, including locks, prediction, target-relative stability state, budgets, hysteresis, fast correction, slow recovery, watchdogs, typed proposed/pending/applied receipts, generation checks, decision history and strict promotion metadata. There is no broad Online/Offline latch: registry presence is not actuation permission, and every source/control reports its own capability. Current game targets without proven source/bounds/rollback/canary/build evidence remain `SHADOW/TEST_REQUIRED`, and protected gameplay/security targets remain permanently blocked. Verified config-only values use automatic snapshot/apply/readback/restore at app-started launch; no unsafe live promotion is implied. |
| L08 Advanced UX | Multi-monitor geometry policy, DPI and accessibility are implemented; HDR and mixed-DPI behavior still need broader target-system observation. Windows system sounds are intentionally absent. |
| L09 Windows hardening | Standard-user portable paths and atomic retry exist. Defender/CFA/WDAC/HVCI matrices require external Windows policy states and are not marked PASS. |
| L10 Supply chain | SBOM, hashes, deterministic build and PE/import validation exist. Signing and external scanners require external credentials/services. |

## Permanent exclusions

X01 gameplay authority, X02 network authority, X03 removal/freezing of living
enemies, X04 guessed telemetry, X05 unknown-address/process-memory injection,
and X06 anti-cheat/kernel/security bypass remain prohibited. The requested FleX
laboratory is a file-bound, explicit offline compatibility experiment and may
not weaken these exclusions.
